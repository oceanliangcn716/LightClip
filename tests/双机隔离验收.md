# 轻剪 0.3.0 双机隔离、群组与文件验收

用户要求：Mac 和 Windows 可能同时运行旧的 CrossPaste，不能把它的传输误判成轻剪成功。本文是实际联调的验收清单，不是已经完成的结果。Mac 本机协议/native 测试、回环夹具和 tests/verification.json 都不能替代真实设备验收；没有可用 Windows PC 时，所有跨机、多 PC、重启和地址变化项目必须标记为“未完成”。

## 准备和证据边界

- 需要一台已完成 0.3.0 群组 UI 与流式文件接线的 Windows PC。当前交接包里的 windows/Program.cs 仍是一对一 WinForms 草稿，但已补文件流和长文字接线，PairingCrypto.cs 是配对加密桥；如果 Windows 尚未完成群组发现、配对、持久化和托盘流程，不得把本轮写成跨机通过。
- Mac 和 Windows 先确认版本、设备名和群组状态。使用合成文字、合成图片和本地测试文件，不读取或收集用户剪贴板正文、文件路径、群组密钥、DPAPI 内容或动态配对码。配对码只在两端 UI 之间手工输入，不写进报告、日志、命令行或聊天。
- 正式测试前，在两端临时正常退出或暂停 CrossPaste，并确认进程不会自动重启。还要排查远程桌面、虚拟机、浏览器扩展和其他剪贴板转发通道；不能操作另一端时由另一端实际确认，不能推测。
- 每个方向和每种状态都使用新生成的合成标记、新测试图片或新文件。不要复制旧剪贴板内容来判定延迟送达；测试结束后说明两端最终状态，不卸载或清除无关软件。

## 0.2.0 群组加入和多 PC

1. 在 Mac 设置窗口保存友好名字，选择“创建同步群组”，确认未配对时没有读取剪贴板或启动内容监听。记录界面状态和群组设备名，不记录密钥。
2. 在 Windows 附近设备列表看到 Mac 的友好名字后，选择它，输入 Mac 当前显示的 8 位短码。确认配对成功后两端显示同一群组状态，并能完成一次明确的群组连接测试。不能用“两端各自生成的密钥”代替同一群组。
3. 至少再加入一台 PC，形成 Mac、PC1、PC2 三个成员，分别确认发现列表、群组状态和地址都来自当前在线设备。验证同一请求可按群组扇出到多个在线目标，单个目标失败不应让其他目标拿到旧内容。若做容量测试，目标上限为 16 个设备、内容连接并发上限为 4 个；未实际达到上限时只报告已测数量。
4. 确认短码有效期为 2 分钟、成功一次即失效；重用已成功短码、错误码或过期码都不能加入群组。不得把失败提示中的配对码或群组密钥写入日志。
5. 若 Mac 原有旧的一对一钥匙串条目，确认升级不会静默清空；同时确认 Windows 未完成群组升级前不能把旧长密钥流程写成 0.2.0 群组互通。

## 重启、自动连接和退出

- 在已有群组的 Mac、PC1、PC2 上分别关闭并重新启动应用或系统。确认群组 ID、设备名和加密存储状态恢复，不要求重新输入群组密钥；如果用户关闭了自动登录，按该设置报告。完成配对后的默认开机自动连接只在实际 UI 和系统登录项都允许时记录为通过。
- 重启后分别做 Mac→PC、PC→Mac 和 Mac→PC2 新内容测试，要求有轻剪自己的加密 ACK、接收写入证据和实际粘贴一致性。不能只凭网络端口可达或对端出现内容判定成功。
- 明确选择“退出群组”只清除本机群组关系并停止同步；本机再次加入应需要新的短码，其他成员仍可留在群组。暂停/恢复不应清除群组配置或 replay 防重放窗口。
- 关闭设置窗口或主窗口后确认应用仍在托盘运行；只有明确选择“退出轻剪”才停止后台同步。

## DHCP 或 Wi‑Fi 地址变化

在至少一个已有群组成员上切换到同一局域网的另一 Wi‑Fi 接入点，或让 DHCP 产生新的地址，并记录变化前后的非敏感地址和时间。等待 UDP 49286 发现更新，确认附近设备显示的来源地址发生变化、TCP 49287 与 49289 更新目标地址后重新连接，不要求用户手工编辑旧 IP。测试期间仍要确保 CrossPaste 没有恢复。无法真实改变地址时，只报告“地址变化未完成”，不能用修改 hosts 或静态配置冒充。

## 内容正向和暂停负对照

每一项都用新标记，覆盖两个方向：

- 文字：中文、emoji、多行和接近上限但小于 1 MiB 的合成文本。
- 图片：截图、透明 PNG，以及文件夹中恰好一张本地 PNG、JPG、JPEG 文件；接收后检查像素或唯一可见标记，不以 PNG 文件字节哈希相同作为唯一依据。
- 普通文件：PDF、ZIP、视频等单文件、多个文件及空文件应通过 49289 保留原字节；在 Finder/Explorer 粘贴成功并核对 SHA-256。单个和整批均限 5 GiB、最多 32 个文件。单 PNG/JPG 同时测试文件粘贴和聊天框图片粘贴。
- 排除：目录、符号链接、reparse point、网络共享路径、非法文件名、超限文件不能被错发成路径或文字；图片附带的 URL/UnicodeText 不得取代实际内容。
- 长文字：测试恰好 10 MiB UTF-8 的合成中文/emoji文字，并在实际编辑器粘贴核对一致性；10 MiB+1 拒绝且不修改远端剪贴板。文字暂存提交后删除。
- 大文件：用合成 5 GiB 文件实传，核对完整字节数、SHA-256、完成 ACK，记录发送/接收的内存、耗时和缓存。取消、中断、复制新内容、暂停时不得粘贴部分文件；未完成临时数据应清理，异常退出后的残留下次启动清理。
- 缓存：已完成文件保留供粘贴，10 GiB 预算要计入并行预留，磁盘不足应拒收并提示；验证“取消当前传输”和“打开接收文件夹”入口。不要手动清理仍被剪贴板引用的文件。
- 回环：远程写入产生的 WM_CLIPBOARDUPDATE 或 Mac 变更通知不能再把同一内容回传，图片和文字都要验证。
- 暂停负对照：在 Mac 暂停、Windows 保持启用时产生新的合成内容；反向再测一次。观察至少 15 秒，暂停期间不得出现 ACK、接收写入或恢复后补发的旧内容。恢复后只发送恢复之后新产生的内容。暂停保留群组和 replay 状态，不能借暂停清空保护窗口。

## CrossPaste 隔离矩阵

以下每一行都要使用全新的合成文字和图片，并在两端实际确认状态：

| CrossPaste 两端 | Mac 轻剪 | Windows 轻剪 | 预期 |
|---|---|---|---|
| 已确认退出/暂停 | 暂停 | 暂停 | 新内容不能同步；否则仍有其他通道 |
| 已确认退出/暂停 | 启用 | 启用 | 新内容能按请求方向同步，有自身 ACK 和接收写入证据 |
| 已确认退出/暂停 | 暂停 | 启用 | Mac 新内容不能到 Windows |
| 已确认退出/暂停 | 启用 | 暂停 | Windows 新内容不能到 Mac |
| 已确认退出/暂停 | 重新启用 | 重新启用 | 再换新内容，确认双向恢复且没有补发旧内容 |
| 任一端 CrossPaste 自动恢复或状态不明 | 任意 | 任意 | 本轮不判定通过，先消除通道再重测 |

正向结果必须同时具备：轻剪自己的合法 ACK、接收端写入证据、接收内容实际可粘贴。对端“看起来出现了内容”或 TCP 端口可连接都不足以归因于轻剪。负对照只证明本轮至少 15 秒观察窗口，不能宣称永久不传输。

## 记录格式和结论

记录设备版本、群组成员数量、方向、内容类别、合成标记、时间、ACK/写入证据和预期结果；不要记录正文、原图、文件路径、密钥或动态短码。把每项标为“通过 / 失败 / 未完成”，并说明失败时是否有其他剪贴板通道。

以下情况不得写“跨机完成”：Windows 端只有旧一对一草稿、Mac 或另一台 PC 不在线、只运行了 loopback/native 夹具、没有加入第二台 PC、没有实际重启或地址变化证据、暂停负对照不成立、CrossPaste 状态不明确。完成单端验证后仍要明确列出“两端联调未完成”。
